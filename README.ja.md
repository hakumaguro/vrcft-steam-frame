# vrcft-steam-frame

**VRChat** で **Steam Frame** のアイトラッキングを使うためのモジュールです。[VRCFaceTracking](https://docs.vrcft.io/)（VRCFT）経由で、
左右それぞれの視線、本物のまばたき、ウィンクに対応します。口のトラッキングはできません。Frame には下半分の顔を撮るカメラがないためです。

> 非公式です。SteamVR が OSC で共有するアイデータと、（任意で）ヘッドセット上の非公開・文書化されていない形式を使います。
> SteamOS や SteamVR のアップデートで、どちらも変わる可能性があります。自己責任でお使いください。

## 必要なもの

| | バージョン |
|---|---|
| Steam Frame | **SteamOS 0.4.3 以降** |
| PC 側の SteamVR | **2.18.2 以降** |
| VRCFaceTracking | Steam 版（5.4.5 で動作確認） |
| アバター | VRCFT のアイトラッキング対応（`FT/v2` パラメータ） |

これらのバージョン以降では、SteamVR が左右それぞれのまぶたの情報を PC に直接送るため、**ヘッドセットには何もインストールする必要がなく**、SSH も不要です。
古いバージョンをお使いの場合は [v0.2.2](https://github.com/hakumaguro/vrcft-steam-frame/releases/tag/v0.2.2) を使ってください。

## 0.3 の新機能

- **キャリブレーション不要になりました。** ヘッドセットをかぶっている間に、モジュールが目の開き具合を学習します（かぶってから約 20 秒後に始まり、数分で落ち着きます）。学習結果は次回のために保存されます。キャリブレーション（メニュー **3**）は任意になり、ウィンクの微調整に使います。
- **SteamVR 自身のまばたき・ウィンク**を左右別々に使い、今日のあなたの目に合った「開いた状態」の基準で処理します。固定値のときより右ウィンクが決まりやすくなり、まばたきでは両目が一緒に閉じます。
- **わかりやすいヘルスチェック：** ステータス（メニュー **2**）が、アイカメラの動作が遅いときやデータが何度も途切れるときに警告します。
- **シンプルになったメニュー：** ヘッドセット側の機能は **A**（Advanced）に移し、オフにするオプションを追加しました。もう必須ではありません。
- 半分閉じた（眠そうな）まぶたを調整できます（`steamVrLid.sleepyLevel`）。また、キャリブレーション中はヘッドセット内にまぶたのライブメーターが表示されます。

## クイックスタート

1. [最新リリース](https://github.com/hakumaguro/vrcft-steam-frame/releases/latest)から **`vrcft-steam-frame-<version>.zip`** をダウンロードし、好きな場所に展開します。
   （ビルド済みのモジュールが入っているので、ほかに何もインストールする必要はありません。ソースコードをダウンロードして使うこともできます。その場合、セットアップがモジュールをビルドし、あなたのユーザー向けに .NET SDK をインストールするか確認します。）
2. **SteamVR を終了**してから **`Start Here.cmd`** をダブルクリックし、**1** を選びます。
   PC 側のすべての設定を行い、VRCFaceTracking を再起動して、結果を**音声で読み上げます**。いつでも再実行できます。正しくなっていない部分だけが変更されます。
3. SteamVR を起動し、ヘッドセットをかぶって遊びます。SteamVR が PC アプリとアイトラッキングデータを共有してよいか尋ねてきたら、**許可（allow）** を選んでください。ヘッドセット内の **"Track Dominant Eye Only"（利き目のみ追跡）はオフ**のままにしてください（VR Settings > General、詳細設定を表示すると出ます）。オンにすると両方のまぶたが片方の目に連動してしまい、ウィンクができなくなります。

うまく動かないときは **2** を選んでください。すべての部分をチェックして、何が問題か、どう直せばよいかを教えてくれます。

数分かぶってもまばたきやウィンクがいまひとつなら、**3** を選んでください（[Python 3](https://www.python.org/downloads/) が必要です）。
音声ガイドに従って、約 70 秒間の「開く・閉じる・ウィンク」の手順を行うと、結果が自動的に適用されます。

**VRCFaceTracking は必ず Steam から起動してください**（メニュー **S** がそれを行います）。`.exe` を直接起動するとモジュールが読み込まれません（VRCFT の仕様上の癖です）。

**0.2.x からのアップデート：** メニュー **1** をもう一度実行してください（設定は引き継がれます）。ヘッドセット側の機能（旧メニュー 2）をインストールしていた場合、
それはもう不要です。また、古いバージョンは SteamOS 0.4.3 以降のアイデータを読めません（無害ですが、再起動を繰り返します）。
**A**、続けて **2** でオフにするか、ヘッドセット上で `systemctl --user disable --now frameeyeosc` を実行してください。これが送信している間は、
モジュールは SteamVR のデータよりもそちらを優先して使います。

## ヘッドセット側の機能（Advanced・任意）

メニュー **A** > **1** で、SSH 経由でヘッドセットに [frameeyeosc](https://github.com/konsti219/frameeyeosc) をインストールします。SteamOS
0.4.3 以降では、追加されるのは 1 点だけです。両目共通ではなく、左右それぞれの視線方向が得られます。これが送信されている間は、モジュールは
まぶたにもそのデータを使い、専用のキャリブレーションを持ちます。そのため、インストールまたは削除したあとはキャリブレーション（メニュー **3**）を行ってください。

1. ヘッドセットで SSH を有効にし（Developer Mode）、**A**、**1** と選んで、ヘッドセットのログイン情報（例：
   `steamos@192.168.1.50`）を入力します。ヘッドセットのパスワードを 1 回入力すると、あとはすべてインストールされ、起動のたびに自動で開始されます。
   不安な場合は、先に [なぜSSH?](#なぜsshヘッドセット側のみ) をお読みください。

   **パスワードの質問はこのように表示されます。** 「authorising the key」の行のあと、ウィンドウは次の表示で止まります。

   ```
   [info ] authorising the key on the headset: enter the headset password when asked (one time only)
   steamos@192.168.1.50's password:
   ```

   ヘッドセットのユーザーアカウントのパスワードを入力して **Enter** を押してください。**入力中は何も表示されません**（点も星印も出ません）。SSH では正常な動作です。
   そのあと `[ok   ] SSH login works` と表示されて先に進みます。`Permission denied, please try again.` と表示された場合はパスワードが違っています（3 回まで試せます。やり直すには **A** > **1** をもう一度実行してください）。
   ヘッドセットにパスワードを設定していない場合は、先にヘッドセット上のターミナルで `passwd` を実行して設定してください。
   すでに自分の SSH 鍵でヘッドセットにログインできる場合（またはパスワード未設定の場合）は、セットアップはそのログインを使って自分の鍵を登録するため、パスワードは聞かれません。ログインに失敗したときは、ssh のメッセージと確認すべき点が表示されます。
2. **A** > **2** でもう一度オフにできます（停止し、自動起動も解除します。ファイルは残ります）。

## 複数の PC でヘッドセットを使う

ヘッドセット側の機能を使わない場合、することは何もありません。各 PC は自分の SteamVR からアイデータを受け取り、各 PC が自分で
開いた状態の基準を学習します。それぞれの PC でメニュー **1** を 1 回実行してください。

ヘッドセット側の機能を使う場合、ヘッドセットはデータを **1 つの** PC アドレスにだけ送ります。**PC を切り替えるたびに、これから使う PC で
A > 1 を実行してください**（ヘッドセットの SSH がオンになっている必要があります。初回以降は数秒で終わります）。それまでは、この PC のモジュールは
SteamVR のデータを使います。それでも動きますが、視線は両目共通になります。各 PC は自分のキャリブレーションを
`steamframe-config.json` に保存します（メニュー **5** でフォルダが開きます）。このファイルは PC 間でコピーできます。

## なぜSSH?（ヘッドセット側のみ）

**要点：** SteamOS 0.4.3 以降と SteamVR 2.18.2 以降では、SSH はまったく必要ありません。ヘッドセット側の機能が追加するのは左右それぞれの視線だけです。
これは*ヘッドセット上で*動かす必要のある小さなプログラムで、SSH は PC がそれをインストールするための手段にすぎません。アイデータ
そのものは SSH を通りません。

**詳しい説明：**

- Frame は専用のカメラで目をトラッキングし、その結果（視線と各まぶたの開き具合）はヘッドセットのメモリ上にあります。Steam Link はその一部を PC に転送します。両目共通の視線と、（SteamOS 0.4.3 / SteamVR 2.18.2 以降は）
  左右それぞれのまぶたの値です。古いバージョンは常に 0 のまぶたの値を送っていたため、以前はヘッドセット側の機能が必要でした。
- [frameeyeosc](https://github.com/konsti219/frameeyeosc) は、ヘッドセット上でそのデータを読み取り、ネットワーク経由（OSC、UDP ポート 9020）で
  PC に送る小さなプログラムです。
- ヘッドセットにプログラムをインストールするには、誰かがヘッドセット上でコマンドを入力する必要があります。**A** > **1** は PC から SSH 経由でそれを行います。
  3 つの小さなスクリプトをコピーし、frameeyeosc をビルドし、ヘッドセットの起動時に開始するよう設定します。

**SSH を使う場面・使わない場面：**

| | SSH は必要？ |
|---|---|
| ヘッドセット側の機能のインストールまたは更新（Advanced > 1） | はい（1 回だけ） |
| 遊んでいる間のアイデータの送信 | **いいえ**：frameeyeosc が直接送るので、SSH はオフで構いません |
| PC 上のすべての操作（メニュー 1-6、S） | いいえ |

**ヘッドセット上で動くもの：** frameeyeosc です。通常のユーザー権限（root ではありません）で動きます。読み取るのはアイトラッキングのデータだけで、
送信先は PC のアドレスだけです。ヘッドセット上でポートは開きません。ソースコード（約 300 行）から
`~/frameeyeosc` にビルドされ、Rust は `~/.cargo` にインストールされます。ホームフォルダの外は何も変更されません。

**セキュリティを高める方法：**

1. SSH は Advanced > 1 のために 1 回だけ使い、そのあと SSH を**もう一度オフに**します（オンにしたときと同じ方法で、またはヘッドセット上で `sudo systemctl disable --now sshd`）。アイトラッキングは引き続き動きます。更新したいときだけ、またオンにしてください。
2. Advanced > 1 は、自分で作成した鍵（`%USERPROFILE%\.ssh\id_ed25519_frame`）でログインします。パスワードは 1 回入力するだけで、保存されません。
   この PC のアクセスを取り消すには、ヘッドセットの `~/.ssh/authorized_keys` からその鍵の行を削除してください。

**SSH をまったく使わない**方法は 2 つあります。

- **ヘッドセット側の機能を使わない。** メニュー 1 だけで、SteamVR 経由の視線・まばたき・ウィンクが使えます（SteamOS 0.4.3 以降、SteamVR 2.18.2 以降）。
- **ヘッドセット自身のデスクトップからインストールする。** Frame のデスクトップモードでターミナルを開き、Advanced > 1 が実行するのと同じスクリプトを、PC のアドレスを指定して実行します
  （PC のアドレスは PC 上で `ipconfig` を実行すると表示されます。ヘッドセットと同じネットワーク上のものを使ってください）。
  ```
  git clone https://github.com/hakumaguro/vrcft-steam-frame ~/vrcft-steam-frame
  bash ~/vrcft-steam-frame/scripts/headset-install.sh <PC-IP>
  ```

**ヘッドセット側の機能を完全に削除するには：**
`systemctl --user disable --now frameeyeosc; loginctl disable-linger $USER; rm -rf ~/frameeyeosc ~/steamframe ~/.config/systemd/user/frameeyeosc.service`
を実行し、Rust も削除する場合は `~/.cargo/bin/rustup self uninstall` を実行します。

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| ウィンクするとアバターの**両目**が閉じる | アバター側でまぶたが連動しています。アバターメニューを開いて **Eye Sync** / "Link eyes" をオフにしてください。ヘッドセットで "Track Dominant Eye Only" がオフになっているかも確認してください。 |
| ステータスに "no eye data at all right now"（今はアイデータがまったく届いていません）と出る | ヘッドセットをかぶり、Steam Link を接続してください。SteamVR が PC アプリとアイトラッキングデータを共有してよいか尋ねてきた場合は、許可してください。メニュー **1** をもう一度実行してください（Steam Link がポート 9015 でアイデータを共有する設定になっているかを確認します）。 |
| ステータスに "only the Steam Link gaze is arriving"（Steam Link の視線しか届いていません）と出る | 視線は動いていますが、まぶたは推測値です。SteamVR がまぶたの値を送っていません。SteamVR（2.18.2 以降）とヘッドセット（SteamOS 0.4.3 以降）を更新してください。 |
| ステータスに "Track Dominant Eye Only is on"（Track Dominant Eye Only がオンです）と出る | 両方のまぶたが片方の目に連動するため、ウィンクができません。ヘッドセットでオフにしてください：VR Settings > General（詳細設定を表示すると出ます）。 |
| ステータスに "eye data is slow"（アイデータが遅いです）と出る | SteamVR がアイカメラを低い頻度で動かしているため、まばたきを取りこぼすことがあります。ヘッドセット上の SteamVR のアイトラッキング設定（`eyeTrackingRateMin`）を確認してください。 |
| 最初の数分、目が半分閉じて見える | モジュールがまだ開いた状態の基準を学習中です（ヘッドセットをかぶってから約 20 秒後に始まります）。そのままなら、キャリブレーション（メニュー **3**）を行ってください。 |
| まばたきが浅い、ウィンクが弱い | メニュー **3**（キャリブレーション）。ウィンクするときにもう片方の目を細める人もいます。キャリブレーションはそれを考慮します。 |
| ステータスに "your settings file has an error"（設定ファイルにエラーがあります）と出る | モジュールは壊れた `steamframe-config.json` を無視し、前の設定を使い続けています。ファイルを直すか、`steamframe-config.json.bak` を復元するか、もう一度キャリブレーション（メニュー **3**）を行ってください。 |
| ステータスに "started without its modules"（モジュールなしで起動しました）と出る | VRCFaceTracking を終了し、Steam から起動してください（メニュー **S**）。 |
| ステータスに古い SteamLink モジュール / ポート 9015 の話が出る | メニュー **1** が標準の SteamLink モジュールを脇に移動します（メニュー **6** のアンインストールで元に戻ります）。 |
| **Module Registry** を開くと VRCFaceTracking が自動的に終了する | 0.2.1 で修正済みです。メニュー **1** を 1 回実行してください（モジュールの `module.json` を修復します）。 |
| ヘッドセット側の機能を使用中：ネットワークを変えたあと、または別の PC を使ったあとにまぶたが動かなくなった | この PC でもう一度 **A** > **1** を実行してください。ヘッドセットの送信先をこの PC に向け直し、ほかはそのまま維持します。 |

ログ（PC）：`%TEMP%\steamframe-module.log`（変化があったときだけ記録され、上限は 1 MB です）。

## メニューの内容

| | |
|---|---|
| 1 セットアップ / 更新 | `scripts\setup.ps1`：どの Steam ライブラリにある VRCFaceTracking も見つけ、モジュールをインストールまたは更新し（キャリブレーションは保持されます）、標準の SteamLink モジュールを脇に移動し、VRCFT の出力先を VRChat のポート 9000 に設定し、Steam Link がポート 9015 でアイデータを共有するよう設定し（SteamVR が終了している間だけ、バックアップ付き）、ファイアウォールのルールを確認し（管理者権限の確認を表示します）、VRCFaceTracking を再起動します。`-DryRun` を付けると、何が変わるかだけを表示します。 |
| 2 ステータス | `scripts\doctor.ps1`：すべての部分をチェックし、要約を音声で読み上げます。 |
| 3 キャリブレーション（任意） | `tools\tune.py calibrate`：音声ガイド（開く、閉じる、ウィンク、まばたき）のあと、目を測定して結果を適用します。記録中は、視界の中央に左右のまぶたの生の値を示す小さなパネルが表示されます（`--no-meter` でオフ、`tune.py meter` でパネルだけ表示）。`--gaze` を付けると、ヘッドセット内に見つめるための点も表示され、視線が何度ずれているかを報告します（報告のみで、補正はまだ行いません）。 |
| 4 ライブビュー | トラッカーの生の値と出力されるまぶたの値を、リアルタイムで表示します。 |
| 5 設定フォルダ | `steamframe-config.json` のあるフォルダを開きます。 |
| 6 アンインストール | モジュールを削除し（キャリブレーションは保存され、再インストール時に復元されます）、標準の SteamLink モジュールを元に戻します。 |
| S VRCFaceTracking を起動 | Steam 経由で起動します（exe を直接起動するとモジュールが読み込まれません）。起動していないときは、メニューがそう表示します。 |
| A Advanced（ヘッドセット側） | SteamOS 0.4.3 以降と SteamVR 2.18 以降では不要です。1：`setup.ps1 -Headset user@host`：SSH 鍵（パスワードは 1 回）、ヘッドセット上で [frameeyeosc](https://github.com/konsti219/frameeyeosc) をビルド（リビジョン固定＋SteamOS 0.4.3 のアイデータ形式向けパッチ。Rust は `~/.cargo`、ホームフォルダの外は何もしません）、ヘッドセットから見える PC のアドレスへ送信する自動起動サービスをインストールします。2：`-HeadsetOff` でもう一度オフにします（停止し、自動起動も解除します。ファイルは残ります）。 |

## 仕組み

| | Steam Link OSC（古いバージョン） | Steam Link OSC（SteamOS 0.4.3 以降 + SteamVR 2.18.2 以降） | + ヘッドセット上の frameeyeosc |
|---|---|---|---|
| 視線 | あり（両目ミラー） | あり（両目ミラー） | あり（左右別々） |
| まばたき | 目の動きから推測 | 本物のまぶたの開き具合 | 本物のまぶたの開き具合 |
| ウィンク | なし | あり（キャリブレーションあり） | あり（キャリブレーションあり） |

SteamOS 0.4.3 / SteamVR 2.18.2 より前は、Frame では Steam Link ドライバのまぶたの値は常に 0 で、左右別々の本物のまぶたの
開き具合はヘッドセットの共有メモリ（`/dev/shm/eye-server.mmap`）にしか存在せず、それを frameeyeosc が読み取って OSC で送っていました。
これらのバージョン以降は、SteamVR が左右それぞれの閉じ具合を自分で送るようになり（`/sl/xrfb/facew/EyesClosedL` と `EyesClosedR`）、
frameeyeosc が送信していないときは、モジュールはそれを使います。本家の frameeyeosc は共有メモリのバージョン 4 を読みます。SteamOS 0.4.3 は
バージョン 5 です（アイのレコードが 5 バイトずれました）。そのため **A** > **1** は、両方を読めるようにする小さなパッチを当ててビルドします。

```
Steam Frame (SteamOS)                                PC (Windows)
  eye tracking service -> /dev/shm/eye-server.mmap
        |                                              VRCFaceTracking
  frameeyeosc  ---- OSC/UDP :9020 (network) ------->   Steam Frame module  --> VRChat (OSC :9000)
                                                            ^
  Steam Link driver ---- OSC/UDP :9015 (this PC) -----------+   (used when frameeyeosc is not sending)
```

Windows 11 と VRCFaceTracking 5.4.5（Steam 版）で動作確認しています。SteamVR 自身のまぶたの値：SteamOS 0.4.3 beta、0.4.5、
0.5.8 beta と、SteamVR 2.18.2 beta、2.19.2 beta、安定版チャンネル（ビルド 25998080、2026-11-10）の組み合わせ。frameeyeosc：SteamOS ビルド 20260922（アイの共有メモリ バージョン 4）
と 0.4.5（バージョン 5、パッチ適用）。

## 手動での調整

モジュールは `steamframe-config.json`（メニュー **5** でフォルダが開きます）を 1 秒以内に再読み込みするので、再起動は不要です。
キャリブレーション（メニュー **3**、任意）が左右別々の基準とまばたき・ウィンクの設定を書き込んでくれます。調整できる項目は次のとおりです。

| キー | 意味 |
|---|---|
| `lid.leftClosed/leftOpen/rightClosed/rightOpen` | トラッカーの生の単位での、左右別々の固定キャリブレーション（null = 自動で適応） |
| `steamVrLid.leftClosed/leftOpen/rightClosed/rightOpen` | SteamVR 自身が送るまぶたの値向けの同様の設定（1 - closed の単位。null = closed は 0 で、open の基準は自動で適応） |
| `steamVrLid.learnOpen` | 既定でオン（null = SteamVR のまぶたではオン）：ヘッドセットをかぶっている間に、モジュールが各目の開いた状態の基準を学習します（開いた目のサンプルの 40 パーセンタイル。主に直近約 10 分のかぶっている時間が対象で、20 秒のウォームアップのあとに始まります。1 秒あたり最大 0.02 しか動かず、次回起動用に `steamframe-learned.json` に保存されます）。そのため、キャリブレーションは不要です。`leftOpen/rightOpen` は出発点としてだけ使われます（新しいキャリブレーションを行うと、そこから学習をやり直します）。`false` = キャリブレーションした値をそのまま使う |
| `steamVrLid.learnMinutes` | 学習した基準が覚えている長さ（かぶっている時間の分数、既定は 10） |
| `steamVrLid.sleepyLevel` | 半分閉じたまぶた：このレベル（閉じ〜開きの範囲の 0..1、両目共通）が `targetSleepy`（0.55）として表示されます。半分閉じた目がアバターで開きすぎて見えるなら上げ、閉じすぎて見えるなら下げてください。キャリブレーションでは設定されません（SteamVR の半分閉じた目の読み取りはセッションごとのばらつきが大きいため）。null = 直線 |
| `steamVrLid.leftSquint/leftSleepy/rightSquint/rightSleepy` | 目を細めたとき・眠そうな（半分閉じた）ときの生のレベル。出力を曲げて、そのポーズが `targetSquint`（0.30）と `targetSleepy`（0.55）として表示されるようにし、その間は直線で結びます。null = 直線。SteamVR のまぶた専用（キャリブレーションが書き込みます） |
| `steamVrLid.filter`（+ `filterMinCutoff / filterBeta`） | One Euro フィルタ：まばたきを遅らせずに、保持した半分閉じのまぶたを安定させます。既定はオフで、キャリブレーションがオンにします |
| `steamVrLid.sharpenBelow / asymHysteresis` | 片方の目がこのレベルを下回っている間だけウィンクを強調します。また、`blink.asymClosed` 付近をうろつく片目の細めが、何度も両目を閉じさせるのを防ぎます。キャリブレーションが設定します |
| `lid.deadband` | 範囲の両端のうち、完全に閉じ／開きと読み取る割合 |
| `wink.threshold / range / strength` | 左右の差を増幅します（strength が 0 = オフ） |
| `wink.assist`（+ `assistOpen / assistClosed / assistMin / assistPersistMs / assistReleaseMs`） | 片目を閉じるともう片方もつられて締まるため、トラッカーはウィンク中にもう片方を半分閉じと報告します。片方の目が下限にあり、もう片方が自分の下限より上の状態が `assistPersistMs` 続いたら、もう片方の目を開いた状態で表示します。既定はオフ |
| `blink.holdMs / releasePerSec` | 最も低いまぶたの値を短時間保持して、速いまばたきでも完全な深さに届くようにします |
| `blink.saturatedRaw / glitchMinMs` | トラッカーはよく、まばたきを「片方のまぶたが閉じ、もう片方が上限（生の値で約 1.0）に張り付く」状態として報告します。それが続く間、両目を閉じます（0 = オフ。frameeyeosc のデータのみ） |
| `blink.coupleMs / asymClosed / asymOpen` | `coupleMs` より短い、その他の左右非対称な閉じ方はまばたきとみなして両目を閉じ、それより長ければウィンクとみなします |
| `gaze.scale / invertX / invertY`, `swapEyes` | 視線のスケールと向きの補正 |
| `trace` | 30 ms ごとのサンプルを常に `%TEMP%\steamframe-trace.csv` に書き込みます。オフのままにしてください（キャリブレーションツールは、必要な間だけ、この設定を使わずに自動でトレースをオンにします） |

コマンドライン：`python tools/tune.py calibrate | record | analyze [--apply] | watch | show | dot`。`calibrate --gaze` は
視線チェックを追加します（ヘッドセット内の 5 か所に表示される点、約 25 秒追加、SteamVR が動いている必要があります）。`dot` は
各位置に点を表示するだけで、ヘッドセットで見えるかを確認するためのものです。

## 既知の制限

- トラッカーは両目を連動させます。片方を閉じるともう片方も半分閉じ気味になります。キャリブレーションとウィンクアシストがこれを補正します。
- VRCFT は `EyeLid = openness x 0.75` を送ります（0.75 が通常の開き。それより上は大きく見開いた状態）。これは VRCFT の規約です。
- 視線のスケール（frameeyeosc は ±45 度を ±1 として送ります）は、基準となるものとの照合をしていません。
- モジュールは UDP 9020 で frameeyeosc からの受信をすべてのネットワークで待ち受けています。同じネットワーク上の誰でもアイデータを送れてしまいます。

## ソースからのビルド

開発用には `scripts\deploy-module.ps1`（ビルド + インストール済み DLL の置き換え + VRCFT の再起動）、
リリース用 zip（ビルド済み DLL 入り。ユーザーは .NET SDK 不要）には `scripts\package.ps1` を使います。.NET 10 SDK と、
インストール済みの VRCFaceTracking（その DLL を参照します）が必要です。
