# vrcft-steam-frame

Eye tracking สำหรับ **Steam Frame** ใน **VRChat** ผ่าน [VRCFaceTracking](https://docs.vrcft.io/) (VRCFT):
ทิศทางการมองแยกทีละตา การกะพริบตา (blink) และการขยิบตา (wink) จริง ส่วน mouth tracking ทำไม่ได้ เพราะ Frame ไม่มีกล้องที่ใบหน้าส่วนล่าง

> ไม่เป็นทางการ ใช้ข้อมูลตาที่ SteamVR แชร์ผ่าน OSC และ (ถ้าเลือก) ฟอร์แมตส่วนตัวที่ไม่มีเอกสารบนเฮดเซ็ต
> การอัปเดต SteamOS หรือ SteamVR อาจทำให้สองอย่างนี้เปลี่ยนไปได้ ใช้ด้วยความเสี่ยงของคุณเอง

## สิ่งที่ต้องมี

| | เวอร์ชัน |
|---|---|
| Steam Frame | **SteamOS 0.4.3 ขึ้นไป** |
| SteamVR บน PC | **2.18.2 ขึ้นไป** |
| VRCFaceTracking | จาก Steam (ทดสอบกับ 5.4.5) |
| อวาตาร์ | รองรับ VRCFT eye tracking (พารามิเตอร์ `FT/v2`) |

ตั้งแต่เวอร์ชันเหล่านี้เป็นต้นไป SteamVR ส่งค่าเปลือกตาของแต่ละตามายัง PC เอง ดังนั้น **ไม่ต้องติดตั้งอะไรบนเฮดเซ็ต**
และไม่ต้องใช้ SSH ถ้าใช้เวอร์ชันเก่ากว่านี้ ให้ใช้ [v0.2.2](https://github.com/hakumaguro/vrcft-steam-frame/releases/tag/v0.2.2)

## มีอะไรใหม่ใน 0.3

- **ไม่ต้อง calibrate** โมดูลจะเรียนรู้ว่าตาคุณเปิดกว้างแค่ไหนขณะสวมเฮดเซ็ต (เริ่มประมาณ 20 วินาทีหลังสวม
  และนิ่งภายในไม่กี่นาที) แล้วจำไว้ใช้ครั้งต่อไป ตอนนี้การ calibrate (เมนู **3**) เป็นตัวเลือก ไว้ปรับจูนการขยิบตา
- **Blink และ wink จาก SteamVR เอง** แยกทีละตา โดยใช้ระดับตาเปิดที่ตรงกับตาของคุณในวันนั้น ขยิบตาขวาทำงานได้บ่อยกว่า
  แบบใช้ค่าคงที่ และการกะพริบตาจะปิดทั้งสองตาพร้อมกัน
- **ตรวจสุขภาพระบบชัดขึ้น:** หน้าสถานะ (เมนู **2**) จะเตือนเมื่อกล้องตาทำงานช้าหรือข้อมูลขาดหายบ่อย
- **เมนูง่ายขึ้น:** ส่วนของเฮดเซ็ตย้ายไปอยู่ที่ **A** (Advanced) และมีตัวเลือกใหม่สำหรับปิดมัน ตอนนี้ไม่จำเป็นต้องใช้อีกแล้ว
- ปรับเปลือกตาที่หรี่ครึ่งหนึ่ง (sleepy) ได้ (`steamVrLid.sleepyLevel`) และตอน calibrate จะมีมิเตอร์เปลือกตาแบบสดแสดงในเฮดเซ็ต

## เริ่มต้นใช้งานอย่างรวดเร็ว

1. ดาวน์โหลด **`vrcft-steam-frame-<version>.zip`** จาก [latest release](https://github.com/hakumaguro/vrcft-steam-frame/releases/latest)
   แล้วแตกไฟล์ไว้ที่ไหนก็ได้ (ในไฟล์มีโมดูลที่คอมไพล์พร้อมใช้แล้ว จึงไม่ต้องติดตั้งอย่างอื่น ถ้าดาวน์โหลดซอร์สโค้ดแทนก็ใช้ได้เช่นกัน:
   setup จะคอมไพล์โมดูลให้และเสนอติดตั้ง .NET SDK ให้กับผู้ใช้ของคุณ)
2. **ปิด SteamVR** จากนั้นดับเบิลคลิก **`Start Here.cmd`** แล้วเลือก **1**
   มันจะตั้งค่าทุกอย่างบน PC รีสตาร์ท VRCFaceTracking และ **พูดบอก** ผลลัพธ์ สั่งรันซ้ำได้ทุกเมื่อ: มันจะเปลี่ยนเฉพาะสิ่งที่ยังไม่ถูกต้อง
3. เปิด SteamVR สวมเฮดเซ็ต แล้วเล่นได้เลย ถ้า SteamVR ถามว่าจะแชร์ข้อมูล eye tracking กับแอปบน PC หรือไม่
   ให้เลือก **allow** และปล่อย **"Track Dominant Eye Only" ไว้เป็นปิด** ในเฮดเซ็ต (VR Settings > General ซึ่งจะแสดงเมื่อเปิดการตั้งค่าขั้นสูง):
   ถ้าเปิดไว้ เปลือกตาทั้งสองข้างจะตามตาข้างเดียว และการขยิบตาจะใช้ไม่ได้

มีอะไรไม่ทำงาน? เลือก **2**: มันจะตรวจทุกส่วนและบอกว่าอะไรผิดและแก้อย่างไร

กะพริบตาหรือขยิบตาแล้วยังไม่ค่อยถูกหลังจากสวมไปได้สักพัก? เลือก **3** (ต้องมี [Python 3](https://www.python.org/downloads/)):
เสียงจะนำทางคุณผ่านขั้นตอนเปิดตา / หลับตา / ขยิบตา ประมาณ 70 วินาที แล้วนำผลไปใช้ให้

**เริ่ม VRCFaceTracking จาก Steam เสมอ** (เมนู **S** ทำให้) การเปิดไฟล์ `.exe` ของมันโดยตรงจะข้ามโมดูล (นิสัยแปลก ๆ ของ VRCFT)

**อัปเดตจาก 0.2.x:** รันเมนู **1** อีกครั้ง (การตั้งค่าของคุณจะถูกเก็บไว้) ถ้าคุณเคยติดตั้งส่วนของเฮดเซ็ต (เมนู 2 แบบเก่า)
ตอนนี้ไม่จำเป็นแล้ว และของเก่าอ่านข้อมูลตาของ SteamOS 0.4.3+ ไม่ได้ (มันจะรีสตาร์ทวนลูป แต่ไม่เป็นอันตราย)
ปิดมันด้วย **A** แล้ว **2** หรือบนเฮดเซ็ตใช้ `systemctl --user disable --now frameeyeosc` ขณะที่มันยังส่งข้อมูลอยู่
โมดูลจะเลือกใช้ข้อมูลของมันก่อนข้อมูลจาก SteamVR

## ส่วนของเฮดเซ็ต (Advanced, ไม่บังคับ)

เมนู **A** > **1** ติดตั้ง [frameeyeosc](https://github.com/konsti219/frameeyeosc) บนเฮดเซ็ตผ่าน SSH บน SteamOS
0.4.3+ มันเพิ่มได้อย่างเดียวคือทิศทางการมองแยกทีละตา แทนที่จะเป็นทิศเดียวสำหรับทั้งสองตา เมื่อมันกำลังส่งข้อมูล โมดูลจะใช้ข้อมูลนั้น
กับเปลือกตาด้วย พร้อมการ calibrate ของมันเอง ดังนั้นให้ calibrate (เมนู **3**) หลังติดตั้งหรือถอดออก

1. เปิด SSH บนเฮดเซ็ต (Developer Mode) จากนั้นเลือก **A**, **1** และใส่ login ของเฮดเซ็ต (เช่น
   `steamos@192.168.1.50`) คุณพิมพ์รหัสผ่านของเฮดเซ็ตครั้งเดียว หลังจากนั้นมันจะติดตั้งทุกอย่างและตั้งให้เริ่มทำงาน
   ทุกครั้งที่บูต ถ้าไม่แน่ใจ อ่าน [ทำไมต้อง SSH?](#ทำไมต้อง-ssh-เฉพาะส่วนบนเฮดเซ็ต) ก่อน

   **หน้าตาของคำถามรหัสผ่าน** หลังบรรทัด "authorising the key" หน้าต่างจะหยุดที่:

   ```
   [info ] authorising the key on the headset: enter the headset password when asked (one time only)
   steamos@192.168.1.50's password:
   ```

   พิมพ์รหัสผ่านของบัญชีผู้ใช้บนเฮดเซ็ตแล้วกด **Enter** **ขณะพิมพ์จะไม่มีอะไรปรากฏ** (ไม่มีจุดหรือดอกจัน)
   เป็นเรื่องปกติของ SSH จากนั้นมันจะแสดง `[ok   ] SSH login works` แล้วทำต่อ ถ้าเห็น
   `Permission denied, please try again.` แปลว่ารหัสผ่านผิด (ลองได้สามครั้ง; รัน **A** > **1** ใหม่เพื่อเริ่มต้นอีกครั้ง) ถ้า
   คุณไม่เคยตั้งรหัสผ่านบนเฮดเซ็ต ให้ตั้งก่อนด้วย `passwd` ในเทอร์มินัลบนเฮดเซ็ต
   ถ้าคุณล็อกอินเข้าเฮดเซ็ตด้วย SSH key ของคุณเองอยู่แล้ว (หรือไม่ได้ตั้งรหัสผ่าน) setup จะใช้ login นั้นเพื่อ
   อนุญาต key ของมัน และจะไม่ถามรหัสผ่านเลย เมื่อ login ล้มเหลว มันจะแสดงสิ่งที่ ssh ตอบกลับมาและสิ่งที่ควรตรวจสอบ
2. **A** > **2** ปิดมันอีกครั้ง (หยุดมันและการเริ่มอัตโนมัติ; ไฟล์ยังอยู่)

## ใช้เฮดเซ็ตกับ PC มากกว่าหนึ่งเครื่อง

ถ้าไม่ใช้ส่วนของเฮดเซ็ต ก็ไม่ต้องทำอะไร: PC แต่ละเครื่องได้ข้อมูลตาจาก SteamVR ของตัวเอง และแต่ละเครื่องเรียนรู้
ระดับตาเปิดด้วยตัวเอง รันเมนู **1** หนึ่งครั้งบน PC ทุกเครื่อง

ถ้าใช้ส่วนของเฮดเซ็ต เฮดเซ็ตจะส่งข้อมูลไปยังที่อยู่ของ PC **เครื่องเดียว** **ทุกครั้งที่สลับ PC ให้รัน A > 1 บน
PC ที่กำลังจะใช้** (ต้องเปิด SSH บนเฮดเซ็ต; หลังครั้งแรกจะใช้เวลาไม่กี่วินาที) จนกว่าจะทำ
โมดูลบน PC เครื่องนี้จะใช้ข้อมูลของ SteamVR ซึ่งก็ใช้ได้เหมือนกัน เพียงแต่เป็นทิศมองเดียวสำหรับทั้งสองตา PC แต่ละเครื่องเก็บ
calibration ของตัวเองใน `steamframe-config.json` (เมนู **5** เปิดโฟลเดอร์ให้) และคุณคัดลอกไฟล์นั้นระหว่าง PC ได้

## ทำไมต้อง SSH? (เฉพาะส่วนบนเฮดเซ็ต)

**สรุปสั้น ๆ:** ด้วย SteamOS 0.4.3+ และ SteamVR 2.18.2+ คุณไม่ต้องใช้ SSH เลย ส่วนของเฮดเซ็ตเพิ่มได้แค่ทิศทางการมอง
ทีละตา มันเป็นโปรแกรมเล็ก ๆ ที่ต้องรัน *บนเฮดเซ็ต* และ SSH เป็นเพียงวิธีที่ PC ใช้ติดตั้งให้คุณ ตัวข้อมูลตา
เองไม่ได้ผ่าน SSH

**แบบละเอียด:**

- Frame ติดตามตาของคุณด้วยกล้องของมันเอง และผลลัพธ์ (ทิศทางการมองและเปลือกตาแต่ละข้างเปิดแค่ไหน) อยู่ในหน่วยความจำของเฮดเซ็ต
  Steam Link ส่งต่อบางส่วนไปยัง PC: ทิศมองเดียวสำหรับทั้งสองตา และ (ตั้งแต่ SteamOS 0.4.3 / SteamVR 2.18.2) เปลือกตา
  ของแต่ละตา เวอร์ชันเก่าส่งค่าเปลือกตาที่เป็น 0 ตลอด ซึ่งเป็นเหตุผลที่เคยต้องมีส่วนของเฮดเซ็ต
- [frameeyeosc](https://github.com/konsti219/frameeyeosc) เป็นโปรแกรมเล็ก ๆ ที่อ่านข้อมูลนั้นบนเฮดเซ็ตแล้วส่ง
  ไปยัง PC ของคุณผ่านเครือข่าย (OSC, UDP พอร์ต 9020)
- การจะติดตั้งโปรแกรมบนเฮดเซ็ต ต้องมีอะไรสักอย่างพิมพ์คำสั่งบนนั้น **A** > **1** ทำสิ่งนี้จาก PC ผ่าน SSH:
  มันคัดลอกสคริปต์เล็ก ๆ สามไฟล์ คอมไพล์ frameeyeosc และตั้งให้เริ่มพร้อมเฮดเซ็ต

**SSH ใช้ทำอะไร และไม่ได้ใช้ทำอะไร:**

| | ต้องใช้ SSH ไหม? |
|---|---|
| ติดตั้งหรืออัปเดตส่วนของเฮดเซ็ต (Advanced > 1) | ใช่ ครั้งเดียว |
| ส่งข้อมูลตาขณะเล่น | **ไม่**: frameeyeosc ส่งโดยตรง ปิด SSH ได้ |
| ทุกอย่างบน PC (เมนู 1-6, S) | ไม่ |

**อะไรรันบนเฮดเซ็ต:** frameeyeosc ในฐานะผู้ใช้ปกติของคุณ (ไม่ใช่ root) มันอ่านเฉพาะข้อมูล eye tracking และส่งไป
ยังที่อยู่ PC ของคุณเท่านั้น มันไม่เปิดพอร์ตใด ๆ บนเฮดเซ็ต มันถูกคอมไพล์จากซอร์สโค้ด (ราว 300 บรรทัด) ใน
`~/frameeyeosc` โดยมี Rust ติดตั้งใน `~/.cargo` ไม่มีอะไรนอกโฟลเดอร์ home ของคุณถูกเปลี่ยน

**ทำให้รัดกุม:**

1. ใช้ SSH ครั้งเดียวสำหรับ Advanced > 1 แล้ว **ปิด SSH** อีกครั้ง (วิธีเดียวกับที่เปิด หรือ `sudo systemctl disable --now sshd`
   บนเฮดเซ็ต) eye tracking ยังทำงานต่อได้ เปิดกลับเมื่อต้องการอัปเดตเท่านั้น
2. Advanced > 1 ล็อกอินด้วย key ที่มันสร้างเอง (`%USERPROFILE%\.ssh\id_ed25519_frame`); รหัสผ่านของคุณพิมพ์ครั้งเดียวและไม่ถูกเก็บ
   หากต้องการเพิกถอนสิทธิ์ของ PC ให้ลบบรรทัดของ key นั้นออกจาก `~/.ssh/authorized_keys` บนเฮดเซ็ต

**ถ้าไม่ใช้ SSH เลย** มีสองทางเลือก:

- **ข้ามส่วนของเฮดเซ็ต** เมนู 1 อย่างเดียวก็ให้ทิศทางการมอง blink และ wink ผ่าน SteamVR (SteamOS 0.4.3+, SteamVR 2.18.2+)
- **ติดตั้งจากเดสก์ท็อปของเฮดเซ็ตเอง** เปิดเทอร์มินัลใน desktop mode ของ Frame แล้วรันสคริปต์เดียวกับที่
  Advanced > 1 จะรัน พร้อมที่อยู่ของ PC (ดูได้จาก `ipconfig` บน PC; ใช้อันที่อยู่เครือข่ายเดียวกับเฮดเซ็ต):
  ```
  git clone https://github.com/hakumaguro/vrcft-steam-frame ~/vrcft-steam-frame
  bash ~/vrcft-steam-frame/scripts/headset-install.sh <PC-IP>
  ```

**ถอดส่วนของเฮดเซ็ตออกทั้งหมด:**
`systemctl --user disable --now frameeyeosc; loginctl disable-linger $USER; rm -rf ~/frameeyeosc ~/steamframe ~/.config/systemd/user/frameeyeosc.service`
และ `~/.cargo/bin/rustup self uninstall` สำหรับ Rust

## การแก้ปัญหา

ข้อความสถานะที่ doctor แสดงเป็นสตริงภาษาอังกฤษจากซอฟต์แวร์ จึงคงไว้ในเครื่องหมายคำพูดตามเดิม

| สิ่งที่คุณสังเกต | ทำสิ่งนี้ |
|---|---|

| สถานะบอกว่า "no eye data at all right now" (ตอนนี้ไม่มีข้อมูลตาเลย) | สวมเฮดเซ็ตและเชื่อมต่อ Steam Link ถ้า SteamVR ถามว่าจะแชร์ข้อมูล eye tracking กับแอปบน PC หรือไม่ ให้อนุญาต รันเมนู **1** อีกครั้ง (มันตรวจว่า Steam Link แชร์ข้อมูลตาที่พอร์ต 9015) |
| สถานะบอกว่า "only the Steam Link gaze is arriving" (มาถึงเฉพาะทิศมองจาก Steam Link) | ทิศมองทำงาน แต่เปลือกตาเป็นการเดา: SteamVR ไม่ส่งค่าเปลือกตา อัปเดต SteamVR (2.18.2+) และเฮดเซ็ต (SteamOS 0.4.3+) |
| สถานะบอกว่า "Track Dominant Eye Only is on" (เปิด Track Dominant Eye Only อยู่) | เปลือกตาทั้งสองตามตาข้างเดียว จึงขยิบตาไม่ได้ ปิดมันในเฮดเซ็ต: VR Settings > General (แสดงเมื่อเปิดการตั้งค่าขั้นสูง) |
| สถานะบอกว่า "eye data is slow" (ข้อมูลตาช้า) | SteamVR รันกล้องตาด้วยอัตราต่ำ จึงอาจพลาดการกะพริบตา ตรวจการตั้งค่า eye-tracking ของ SteamVR บนเฮดเซ็ต (`eyeTrackingRateMin`) |
| ตาดูหรี่ครึ่งหนึ่งในไม่กี่นาทีแรก | โมดูลยังเรียนรู้ระดับตาเปิดของคุณอยู่ (เริ่มประมาณ 20 วินาทีหลังสวมเฮดเซ็ต) ถ้ายังเป็นอยู่ ให้ calibrate (เมนู **3**) |
| กะพริบตาตื้นเกินไป ขยิบตาอ่อน | เมนู **3** (calibrate) บางคนหรี่ตาอีกข้างตอนขยิบ การ calibrate คำนึงถึงเรื่องนี้แล้ว |
| สถานะบอกว่า "your settings file has an error" (ไฟล์ตั้งค่าของคุณมีข้อผิดพลาด) | โมดูลไม่ใช้ `steamframe-config.json` ที่เสียและคงการตั้งค่าก่อนหน้าไว้ แก้ไฟล์ กู้คืน `steamframe-config.json.bak` หรือ calibrate ใหม่ (เมนู **3**) |
| สถานะบอกว่า "started without its modules" (เริ่มโดยไม่มีโมดูล) | ปิด VRCFaceTracking แล้วเริ่มจาก Steam (เมนู **S**) |
| สถานะพูดถึงโมดูล SteamLink เก่า / พอร์ต 9015 | เมนู **1** ย้ายโมดูล SteamLink มาตรฐานออกไป (เมนู **6** uninstall จะนำกลับมา) |
| VRCFaceTracking ปิดตัวเองเมื่อเปิด **Module Registry** | แก้แล้วใน 0.2.1: รันเมนู **1** หนึ่งครั้ง (มันซ่อมแซม `module.json` ของโมดูล) |
| เมื่อใช้ส่วนของเฮดเซ็ต: เปลือกตาหยุดทำงานหลังเปลี่ยนเครือข่ายหรือหลังใช้ PC เครื่องอื่น | รัน **A** > **1** อีกครั้งบน PC เครื่องนี้: มันชี้เฮดเซ็ตมาที่นี่และคงส่วนที่เหลือไว้ |

Logs (PC): `%TEMP%\steamframe-module.log` (บันทึกเฉพาะการเปลี่ยนแปลง จำกัดที่ 1 MB)

| Blink (กะพริบตา) | เดาจากการเคลื่อนไหวของตา | ค่าเปลือกตาเปิดจริง | ค่าเปลือกตาเปิดจริง |
| Wink (ขยิบตา) | ไม่ได้ | ได้ (ต้อง calibrate) | ได้ (ต้อง calibrate) |

ก่อน SteamOS 0.4.3 / SteamVR 2.18.2 ค่าเปลือกตาของไดรเวอร์ Steam Link เป็น 0 ตลอดบน Frame และค่าเปลือกตาเปิดจริงแยกทีละตา
มีอยู่เฉพาะในหน่วยความจำร่วมของเฮดเซ็ต (`/dev/shm/eye-server.mmap`) ซึ่ง frameeyeosc อ่านและส่งผ่าน OSC
ตั้งแต่เวอร์ชันเหล่านั้นเป็นต้นมา SteamVR ส่งค่าการปิดของแต่ละตาเอง (`/sl/xrfb/facew/EyesClosedL` และ `EyesClosedR`) และ
โมดูลใช้ค่านั้นเมื่อใดก็ตามที่ frameeyeosc ไม่ได้ส่ง frameeyeosc ต้นฉบับอ่าน shared-memory เวอร์ชัน 4; SteamOS 0.4.3 เป็น
เวอร์ชัน 5 (ตำแหน่งข้อมูลตาขยับไป 5 ไบต์) ดังนั้น **A** > **1** จึงคอมไพล์มันพร้อมแพตช์เล็ก ๆ ที่อ่านได้ทั้งสองเวอร์ชัน

```
Steam Frame (SteamOS)                                PC (Windows)
  eye tracking service -> /dev/shm/eye-server.mmap
        |                                              VRCFaceTracking
  frameeyeosc  ---- OSC/UDP :9020 (network) ------->   Steam Frame module  --> VRChat (OSC :9000)
                                                            ^
  Steam Link driver ---- OSC/UDP :9015 (this PC) -----------+   (used when frameeyeosc is not sending)
```

ทดสอบกับ Windows 11 และ VRCFaceTracking 5.4.5 (Steam) ค่าเปลือกตาของ SteamVR เอง: SteamOS 0.4.3 beta, 0.4.5 และ
0.5.8 beta กับ SteamVR 2.18.2 beta, 2.19.2 beta และช่อง stable (build 25998080, 2026-11-10) frameeyeosc: SteamOS build 20260922 (eye shared-memory เวอร์ชัน 4)
และ 0.4.5 (เวอร์ชัน 5, แพตช์แล้ว)

## ปรับจูนด้วยมือ

โมดูลโหลด `steamframe-config.json` ใหม่ภายในหนึ่งวินาที (เมนู **5** เปิดโฟลเดอร์ของมัน) ไม่ต้องรีสตาร์ท
การ calibrate (เมนู **3**, ไม่บังคับ) เขียนระดับรายตาและค่าตั้ง blink/wink ให้คุณ ส่วนด้านล่างคือปุ่มปรับต่าง ๆ:

| key | ความหมาย |
|---|---|
| `lid.leftClosed/leftOpen/rightClosed/rightOpen` | calibration รายตาแบบคงที่ ในหน่วยดิบของตัวติดตาม (null = ปรับอัตโนมัติ) |
| `steamVrLid.leftClosed/leftOpen/rightClosed/rightOpen` | แบบเดียวกัน สำหรับค่าเปลือกตาที่ SteamVR ส่งมาเอง (หน่วยคือ 1 - closed; null = closed เป็น 0 และระดับตาเปิดปรับเอง) |
| `steamVrLid.learnOpen` | เปิดเป็นค่าเริ่มต้น (null = เปิดสำหรับเปลือกตาของ SteamVR): โมดูลเรียนรู้ระดับตาเปิดของแต่ละตาขณะที่คุณสวมเฮดเซ็ต (เปอร์เซ็นไทล์ที่ 40 ของตัวอย่างตาเปิด ส่วนใหญ่จากราว 10 นาทีล่าสุดที่สวม หลังวอร์มอัพ 20 วินาที; ขยับได้มากสุด 0.02 ต่อวินาที และบันทึกใน `steamframe-learned.json` ไว้ใช้ตอนเริ่มครั้งต่อไป) คุณจึงไม่ต้อง calibrate `leftOpen/rightOpen` จึงเป็นเพียงจุดเริ่มต้น (calibration ใหม่จะเริ่มการเรียนรู้ใหม่จากค่าเหล่านั้น) `false` = ใช้ระดับที่ calibrate ไว้ตามนั้น |
| `steamVrLid.learnMinutes` | ระดับที่เรียนรู้จำได้นานแค่ไหน หน่วยเป็นนาทีที่สวม (ค่าเริ่มต้น 10) |
| `steamVrLid.sleepyLevel` | เปลือกตาหรี่ครึ่ง: ระดับนี้ (0..1 ของช่วง closed-open ทั้งสองตา) จะถูกแสดงเป็น `targetSleepy` (0.55) เพิ่มค่าถ้าตาหรี่ครึ่งดูเปิดเกินไปบนอวาตาร์ ลดค่าถ้าดูปิดเกินไป การ calibrate ไม่ตั้งค่านี้ (ค่าที่ SteamVR อ่านได้จากตาที่หรี่ครึ่งต่างกันมากระหว่างเซสชัน); null = เส้นตรง |
| `steamVrLid.leftSquint/leftSleepy/rightSquint/rightSleepy` | ระดับดิบขณะหรี่ตา (squint) และขณะตาง่วง (sleepy, หรี่ครึ่ง) ค่าเหล่านี้ดัดเอาต์พุตให้ท่าทางเหล่านั้นแสดงเป็น `targetSquint` (0.30) และ `targetSleepy` (0.55) โดยช่วงระหว่างเป็นเส้นตรง null = เส้นตรง ใช้กับเปลือกตาของ SteamVR เท่านั้น (calibration เขียนค่าเหล่านี้ให้) |
| `steamVrLid.filter` (+ `filterMinCutoff / filterBeta`) | ฟิลเตอร์ One Euro: ทำให้เปลือกตาที่ค้างปิดบางส่วนนิ่งขึ้นโดยไม่ทำให้การกะพริบตาช้าลง ปิดเป็นค่าเริ่มต้น; calibration จะเปิดให้ |
| `steamVrLid.sharpenBelow / asymHysteresis` | เพิ่มความคมของ wink เฉพาะเมื่อตาข้างหนึ่งต่ำกว่าระดับนี้ และกันไม่ให้การหรี่ตาข้างเดียวที่วนอยู่ใกล้ `blink.asymClosed` ทำให้ปิดทั้งสองตาซ้ำแล้วซ้ำอีก calibration ตั้งค่าเหล่านี้ให้ |
| `lid.deadband` | สัดส่วนของช่วงที่ปลายแต่ละด้านที่อ่านว่าปิดเต็มที่ / เปิดเต็มที่ |
| `wink.threshold / range / strength` | ขยายความไม่สมมาตรซ้าย/ขวา (strength 0 = ปิด) |
| `wink.assist` (+ `assistOpen / assistClosed / assistMin / assistPersistMs / assistReleaseMs`) | การหลับตาข้างหนึ่งทำให้อีกข้างตึงตามไปด้วย ตัวติดตามจึงรายงานว่าอีกข้างปิดบางส่วนระหว่างขยิบ เมื่อตาข้างหนึ่งอยู่ที่ระดับต่ำสุดและอีกข้างอยู่เหนือระดับต่ำสุดของตัวเองนาน `assistPersistMs` ให้แสดงตาอีกข้างเป็นเปิด ปิดเป็นค่าเริ่มต้น |
| `blink.holdMs / releasePerSec` | ค้างค่าเปลือกตาต่ำสุดไว้สั้น ๆ เพื่อให้การกะพริบเร็วลงถึงความลึกเต็ม |
| `blink.saturatedRaw / glitchMinMs` | ตัวติดตามมักรายงานการกะพริบเป็นเปลือกตาข้างหนึ่งปิดขณะที่อีกข้างค้างอยู่ที่เพดาน (ดิบ ~1.0); ตราบที่เป็นแบบนี้ ให้ปิดทั้งสองตา (0 = ปิด; ใช้กับข้อมูลจาก frameeyeosc เท่านั้น) |
| `blink.coupleMs / asymClosed / asymOpen` | การปิดแบบไม่สมมาตรอื่นใดที่สั้นกว่า `coupleMs` ถือเป็นการกะพริบและปิดทั้งสองตา ที่นานกว่านั้นถือเป็นการขยิบ |
| `gaze.scale / invertX / invertY`, `swapEyes` | การปรับสเกลและแก้ทิศทางของทิศมอง |
| `trace` | เขียนตัวอย่างทุก 30 ms ลง `%TEMP%\steamframe-trace.csv` ตลอดเวลา ควรปิดไว้ (เครื่องมือ calibrate เปิด trace เองเฉพาะตอนที่ต้องใช้ โดยไม่ต้องพึ่งการตั้งค่านี้) |

บรรทัดคำสั่ง: `python tools/tune.py calibrate | record | analyze [--apply] | watch | show | dot` `calibrate --gaze` เพิ่ม
การตรวจทิศมอง (จุดในเฮดเซ็ต 5 ตำแหน่ง ใช้เวลาเพิ่ม 25 วินาที ต้องเปิด SteamVR อยู่); `dot` แสดงเพียงจุดที่แต่ละ
ตำแหน่ง เพื่อตรวจว่ามองเห็นในเฮดเซ็ตหรือไม่

## ข้อจำกัดที่ทราบ

- ตัวติดตามเชื่อมสองตาเข้าหากัน: หลับตาข้างหนึ่งดึงอีกข้างให้หรี่ลงครึ่งหนึ่ง การ calibrate และ wink assist ช่วยชดเชย
- VRCFT ส่ง `EyeLid = openness x 0.75` (0.75 คือเปิดปกติ; สูงกว่านั้นหมายถึงตาเบิกกว้าง) นี่เป็นธรรมเนียมของ VRCFT
- สเกลทิศมอง (frameeyeosc ส่ง +-1 แทน +-45 องศา) ยังไม่ได้ตรวจเทียบกับตัวอ้างอิง
- โมดูลฟัง frameeyeosc ที่ UDP 9020 บนทุกเครือข่าย ใครก็ตามในเครือข่ายของคุณสามารถส่งข้อมูลตาให้มันได้

## การคอมไพล์จากซอร์ส

`scripts\deploy-module.ps1` (คอมไพล์ + แทนที่ DLL ที่ติดตั้ง + รีสตาร์ท VRCFT) สำหรับการพัฒนา
`scripts\package.ps1` สำหรับ zip รุ่นเผยแพร่ที่มี DLL คอมไพล์ไว้แล้ว (ผู้ใช้ไม่ต้องมี .NET SDK) ต้องมี .NET 10 SDK และ
VRCFaceTracking ที่ติดตั้งแล้ว (DLL ของมันถูกอ้างอิง)
